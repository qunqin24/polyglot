# WebUI 在高延迟线路上的加载

页面数据保存在当前标签页的内存中。15 秒内重复访问复用结果；超过 15 秒先显示已有结果，再后台更新。离开页面超过 5 分钟的缓存可被回收，最多保留 100 个闲置查询。完整日志正文和显示出来的密钥不进入这个缓存，也不写入浏览器持久存储。

同一查询的并发读取和重复刷新合并为一个请求。保存配置后会使查询过期并更新正在显示的数据；保存前发出的慢请求不能覆盖新结果。退出登录或接口返回未认证状态时清空缓存。后台标签页暂停周期刷新。

新增 `useAsync` 调用时，查询键必须包含数据名称和所有筛选参数，例如 `["models", providerID, search, 500]`。读取同一份数据的页面使用相同键；包含翻译后的选项时，键也须区分语言。

首次打开时，初始化状态和登录状态并行获取。内嵌网页和 `/api` 管理接口支持 HTTP 压缩；模型接口不使用这层压缩。带指纹的静态资源沿用长期缓存，HTML 入口重新验证，以便升级后加载新版本。

本地直连测试中，当前构建的 JS/CSS 从约 759 KB 压缩到 229 KB，减少约 70%。这是传输字节数的对比，不是 VPS 页面耗时的实测；如果反向代理已经压缩资源，这部分收益可能已存在。首次访问尚未缓存的数据仍需一次网络请求。

自动化验证包括模拟 300 毫秒慢请求、重复请求合并、缓存复用、刷新失败、编辑与慢请求竞态、会话清理、缓存回收，以及真实 HTTP 压缩和模型流式响应检查。运行 `make check`；压缩的独立并发检查为 `go test -race ./internal/api -run TestWebUI -count=1`。

实现参考：[React 关于客户端缓存与请求合并的说明](https://react.dev/reference/react/useEffect#what-are-good-alternatives-to-data-fetching-in-effects)、[MDN HTTP 缓存说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)。
